# Agents

This file provides guidance for AI coding agents working on the Leaflet codebase.

## Project Overview

Leaflet is an open-source JavaScript library for building mobile-friendly interactive maps. It is lightweight (~40 kB gzipped JS + 3.2 kB gzipped CSS) and emphasises simplicity, performance and usability.

## Key Commands

- **Install dependencies:** `npm install`
- **Build:** `npm run build`
- **Lint:** `npm run lint`
- **Lint and fix:** `npm run lintfix`
- **Run tests:** `npm test -- --single-run` (requires Google Chrome)
- **Run tests in a specific browser:** `npm test -- --browsers Firefox --single-run`
- **Generate docs:** `npm run docs`
- **Watch mode (rebuild on change):** `npm run watch`

## Project Structure

```
src/           - Source code
  core/        - Base Class system, Evented pattern, utilities
  dom/         - Cross-browser DOM utilities and event normalisation
  geo/         - Geographical coordinate systems (LatLng), CRS, projections
  geometry/    - Cartesian primitives (Point, Bounds), transformations
  layer/       - Tiles, Markers, Popups, GeoJSON, vector layers
  map/         - Core Map logic and viewport state management
  control/     - UI controls (Zoom, Attribution, Layers, Scale)
  images/      - Icons and image assets
spec/          - Test suites (Mocha + Karma)
dist/          - Compiled production bundles (ESM and UMD) - generated, do not edit
build/         - Build scripts (Rollup config, Leafdoc, integrity)
docs/          - Jekyll-based documentation site and plugin registry
debug/         - Development/debugging HTML pages
```

## Coding Conventions

- **Indentation:** Use tabs for indentation and spaces for alignment.
- **ES Modules:** The project uses ES module syntax (`import`/`export`). The `"type": "module"` field is set in `package.json`.
- **File extensions:** Always include `.js` extensions in import paths (enforced by the `import/extensions` ESLint rule).
- **Linting:** ESLint is configured via `eslint.config.js` using `eslint-config-mourner` as a base. Run `npm run lint` before committing.
- **Pre-commit hooks:** Husky runs `lint-staged` on commit, which auto-fixes lint issues on staged `.js`, `.mjs` and `.md` files.
- **No mixed spaces and tabs:** Smart tabs are enforced - tabs for indentation, spaces for alignment after the initial tabs.
- **Curly braces:** Always required (the `curly` rule is set to `error`).
- **Spaced comments:** Comments must have a space after `//` or `/*`.
- **Prefer modern syntax:** `prefer-exponentiation-operator` and `prefer-object-has-own` are enforced.
- **No unused variables:** Enforced, with caught errors excluded.
- **CSS:** Uses `@eslint/css` with baseline rules; `!important` triggers a warning.

## Key Concepts

- **LatLng** - Geographic coordinates (latitude, longitude, optional altitude).
- **Point** - Pixel coordinates (x, y) relative to a container or origin.
- **CRS** - Coordinate Reference System; maps the Earth to a flat plane.
- **Layer** - Any object rendered on the map (tiles, vectors, UI elements).
- **Pane** - Z-indexed DOM container for managing layer stacking order.
- **GridLayer** - Base for tiled content; handles tile pruning and loading.
- **Renderer** - SVG or Canvas backend for drawing vector paths.
- **Evented** - Internal observer pattern supporting event bubbling.

## Testing

- Tests are in `spec/suites/` and use **Mocha** as the test framework with **Chai** for assertions.
- Tests run via **Karma** (configured in `spec/karma.conf.cjs`).
- Ensure the project is built before running tests (`npm run build`).
- SSR tests exist in `spec/ssr/` for Node.js and Deno environments.

## Important Notes

- Do not edit files in `dist/` directly; they are generated by the build step.
- The API documentation is generated from Leafdoc comments in the source code. Edit source comments to update API docs.
- Each batch of changes should be in its own topic branch; do not commit to `main` directly.
- Line endings must be configured properly in Git.
- The library targets broad browser support including mobile. Use the `baseline-js/use-baseline` ESLint rule as a guide for which Web APIs are safe to use.
